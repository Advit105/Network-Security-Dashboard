Hash Results

Verify Hash

Check if a string matches a known hash — useful for verifying file integrity.

Algorithm status
  • SHA-256256-bit · industry standard — recommended for new work
  • SHA-512512-bit · stronger and often faster on 64-bit CPUs
  • SHA-1160-bit · broken — practical collisions since 2017, legacy verification only
Hashing ≠ encryption
  • one-wayYou can't reverse a hash back into the input
  • deterministicThe same input always gives the same digest
  • avalancheChange one character and the whole hash changes
Where hashes are used
  • integrityVerify a download matches the checksum the vendor published
  • forensicsMalware samples are identified by their SHA-256
  • passwordsStored as salted hashes — but with a slow KDF (bcrypt, Argon2), never raw SHA

Record cheat sheet
  • AHostname → IPv4 address
  • AAAAHostname → IPv6 address
  • MXMail servers that accept email for the domain
  • TXTFree text — SPF policies, domain-ownership proofs
  • NSThe authoritative nameservers
  • CNAMEAlias pointing one name at another
What TTL means

Time-to-live is how many seconds resolvers may cache the answer. A low TTL (60–300) means the owner wants fast changes — common right before a migration or failover. A high TTL (86400) means a stable, rarely-moved record.

SOC uses
  • SPF auditRead TXT records to see who may send mail as the domain
  • infra mapNS + MX reveal which providers a target actually uses
  • takeoverA CNAME pointing at a deprovisioned service is a subdomain-takeover risk

Squatting techniques

SPF — who may send

A TXT record listing the servers allowed to send mail for the domain. Anything else fails the check.

v=spf1 include:_spf.google.com ~all
DKIM — proof it's untampered

Outgoing mail is cryptographically signed; receivers fetch the public key from selector._domainkey DNS to verify the message wasn't altered in transit.

DMARC — the enforcement policy
  • p=noneMonitor only — spoofed mail still gets delivered
  • p=quarantineFailures go to spam
  • p=rejectFailures are refused outright — the goal state

The #1 phishing tell

                            
Reply-To ≠ From. The attacker spoofs a trusted From: address for display, but replies must reach a mailbox they control. Auth can even pass — for the attacker's own domain — which is why alignment with the From: domain matters more than a green "pass".

Why age matters

                            
Attackers register fresh domains constantly. A brand look-alike created this week that's already sending mail is almost never legitimate — age is one of the highest-signal, lowest-effort checks in triage.

RDAP vs WHOIS

                            
RDAP is the IETF replacement for legacy WHOIS: structured JSON, standardized fields, and CORS-enabled — which is exactly why this runs in your browser with no key. ASN vs IP

                            
An ASN is a network operator's ID; the prefix is the block of addresses they announce to the internet. Blocking a whole malicious prefix can be smarter than chasing individual IPs that rotate within it.
